# 講師手冊

## 教學原則

1. 先用高爾夫建立直覺，再回到企業規格。
2. 每講一個名詞，立刻讓學員填一個真實欄位。
3. 不把工具操作當方法論；工具只示範其中一支球桿。
4. 對高風險案例，優先教會「停止與升級」。
5. 以成果證據評量，不以回答流暢度評量。

## 開場腳本

> 如果同一洞每一球都拿 Driver，問題通常不是球桿不夠好，而是沒有球場管理。企業 AI 也一樣：真正要建立的不是「人人都用最強模型」，而是讓組織知道何時攻、何時守、何時交給人，並把成功打法留下來。

## 常見誤解與追問

| 誤解 | 講師追問 |
| --- | --- |
| VAC 就是 Prompt Template | 它的權限、失敗處理、Verify、Owner 與 Expiry 在哪裡？ |
| Memory 越多越好 | 過期、衝突、無來源的記憶如何處理？ |
| 高階模型可以解決高風險 | 高能力是否等於有授權、有證據、有責任？ |
| Workflow 跑通就成功 | 商業 KPI、品牌與重大錯誤是否通過？ |
| Agent 就是不必人工 | 哪些決策依法規、倫理或責任仍必須由人核准？ |

## 示範順序

1. 展示一句模糊需求。
2. 建立 VAD，讓資料缺口與風險浮現。
3. 加入 Memory，故意放一筆過期資料讓學員辨識。
4. 比較攻、守、停止三種 Decision。
5. 最後才選模型、工具與 Workflow。
6. 用 Verify 讓一個「看起來很好」的輸出被退回。
7. 說明修正後如何形成 VAC。

## 時間管理

- 講授不超過總時間 40%。
- 每 30–45 分鐘至少一次產出或同儕檢查。
- 工作坊最後保留至少 30 分鐘發表與修正。

## 安全與隱私

要求學員使用去識別化資料；禁止在公開工具輸入公司秘密、個資、未公開財務、人事或客戶資料。重大專業判斷僅作流程設計演練，不輸出實際決策。
